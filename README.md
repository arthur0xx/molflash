# chrigsm — كتالوج أدوات وخدمات GSM

مشروع عربي RTL لتنظيم وعرض أدوات وخدمات GSM. يعرض الموقع **الأداة الأساسية مرة واحدة**، ثم يجمع داخل صفحتها باقاتها ومددها وخيارات التجديد أو الرصيد؛ لذلك لا تتكرر الهوية البصرية عندما تختلف مدة الخدمة فقط.

## التقنية

| الطبقة | التقنية |
|---|---|
| الواجهة | React + Vite |
| الخادم | Node.js + Express |
| قاعدة البيانات | SQLite عبر `better-sqlite3` |
| الكتالوج | ملف ثابت محلي داخل `backend/src/data/gsm-services.json` |
| التخزين الخارجي | Google Drive لنسخ البيانات والأصول المنظمة فقط |

## المبدأ التشغيلي

لا يتصل المشروع حالياً بأي API خارجي لتنفيذ الطلبات أو تحديث الخدمات. تُستورد قائمة الخدمات من ملف JSON ثابت عند إنشاء قاعدة بيانات جديدة، ثم تُعرض في الواجهة كتجميعة أدوات وباقات. هذا يسمح لك بمراجعة المحتوى والصور والأسعار قبل تفعيل أي ربط تشغيلي مستقبلي.

> لكل أداة صورة وهوية واحدة. لا تُنشأ صورة منفصلة لخيار شهر أو 3 أشهر أو سنة أو رصيد أو تجديد.

## التشغيل محلياً

انسخ قالب البيئة أولاً ثم استبدل القيم الوصفية بقيمك الحقيقية. لا ترفع ملف `backend/.env` إلى Git.

```bash
# الخادم — المنفذ 3001
cd backend
cp .env.example .env
# عدّل .env: ضع JWT_SECRET ومدير الموقع عند إنشاء قاعدة بيانات جديدة
npm install
npm start

# الواجهة — المنفذ 5173
cd ../frontend
npm install
npm run dev
```

## إنشاء المدير لأول مرة

لا ينشئ المشروع أي حساب مدير تجريبي. تُقرأ متغيرات `ADMIN_NAME` و`ADMIN_PHONE` و`ADMIN_PASSWORD` من `backend/.env` أو من منصة الاستضافة عند إنشاء قاعدة بيانات جديدة فقط. بعد إنشاء المدير، احذف متغيرات المدير من بيئة الإنتاج أو اتركها غير مضبوطة؛ ستظل بيانات المدير محفوظة في قاعدة البيانات.

يجب أن تكون قيمة `JWT_SECRET` عشوائية وطويلة وفريدة. يرفض الخادم التشغيل بـ`NODE_ENV=production` إذا لم تكن هذه القيمة موجودة.

## بنية الخدمات

توجد كل البيانات المصدرية في:

```text
backend/src/data/gsm-services.json
```

عند تشغيل الخادم لأول مرة، ينشئ المستورد:

| العنصر | الوصف |
|---|---|
| التصنيف | مجموعة الخدمة المصدرية. |
| الأداة | اسم موحد مثل `Unlock Tool`. |
| الباقة | مدة أو تجديد أو رصيد أو خيار محدد. |
| الحقول المطلوبة | حقول ديناميكية تظهر عند إتمام الطلب وفق الخدمة المختارة. |
| الأصل البصري | صورة الأداة إن توفرت، وإلا الصورة الافتراضية الموحدة. |

## واجهات API الرئيسية

| المسار | الاستخدام |
|---|---|
| `GET /api/tools` | قائمة الأدوات الأساسية مع عدد الباقات وسعر البداية. |
| `GET /api/tools/:toolKey` | تفاصيل أداة واحدة وباقاتها المتاحة. |
| `GET /api/products` | واجهة الباقات القديمة، تبقى للتوافق مع السلة والطلبات. |
| `POST /api/orders` | إنشاء طلب محلي من رصيد المحفظة؛ لا يرسل طلباً إلى مزود خارجي. |

## الأصول والصور

يوجد أصل افتراضي موحد في:

```text
frontend/public/assets/chrigsm-default-service-hero.png
```

يمكن استبدال الاسم التقني للملف لاحقاً، لكنه لا يظهر كاسم علامة للمستخدم. عندما تتوفر صورة موثوقة لأداة ما، ضعها في:

```text
frontend/public/assets/tools/<tool-key>.png
```

ثم حدّث حالة الأصل في سجل الصور. من لوحة الإدارة افتح **الأدوات والباقات** ثم اضغط **تصدير الصور الناقصة** لتنزيل قائمة الأدوات التي تحتاج مراجعة، مع اسم الملف والمسار المقترحين. راجع فهرس الصور الذي سيُحفظ في Google Drive قبل اعتماد أي أصل جديد.

## ملاحظات الإنتاج

اضبط `NODE_ENV=production` و`JWT_SECRET` و`CORS_ORIGIN` دائماً في بيئة الإنتاج. يمكن أن يتضمن `CORS_ORIGIN` نطاقاً واحداً أو عدة نطاقات مفصولة بفواصل. أضف rate limiting وCSP ونسخاً احتياطية لقاعدة البيانات قبل نشر الموقع للعامة. تدار بيانات WhatsApp الاختيارية من لوحة الإدارة، ولا يوجد حالياً ربط لتنفيذ الطلبات مع مزود خدمات خارجي.
