# ChriGsm — Next.js + Firebase

تطبيق ChriGsm لمتجر الخدمات الرقمية، ومنطقة حساب العميل، ولوحة إدارة CMC. يعتمد المشروع على Next.js للواجهة ومسارات الخادم، وعلى Firebase للمصادقة والبيانات، مع تكامل مهيأ لتخزين الوسائط. تعتمد الواجهة على البيانات التشغيلية المتاحة فقط؛ وعند غياب بيانات الكتالوج تظهر حالات فارغة آمنة بدل أي محتوى افتراضي.

## التطوير والتحقق

شغّل `npm run dev` ثم افتح `http://localhost:3000`. قبل النشر، استخدم `npm run lint` ثم `npm run build` للتحقق من جودة الشيفرة وبناء الإنتاج.

| الأمر | الغرض |
|---|---|
| `npm run dev` | تشغيل معاينة محلية مع التحديث الفوري |
| `npm run lint` | فحص جودة الشيفرة |
| `npm run build` | تحقق من بناء الإنتاج |
| `npm run emulators` | تشغيل محاكيات Firebase محليًا عند الحاجة |
| `npm run test:firestore-rules` | اختبار قواعد Firestore محليًا |

## الإعداد

انسخ `.env.example` إلى `.env.local` وأضف قيم تطبيق Firebase العامة وقيم Firebase Admin الخادمية. لا ترفع ملف `.env.local` أو مفتاح الخدمة إلى Git. انشر `firestore.rules` و`storage.rules` من Firebase CLI بعد مراجعة القواعد.

يجب أن يشير `NEXT_PUBLIC_APP_URL` إلى عنوان HTTPS العام للتطبيق، لأنه يستخدم لإنشاء روابط ChriGsm المخصصة لتأكيد البريد الإلكتروني وإعادة تعيين كلمة المرور. ويجب أن يشير `NEXT_PUBLIC_SITE_URL` إلى العنوان الأساسي نفسه ليُستخدم في الروابط القانونية وبيانات SEO ووسوم Open Graph.

### Google Search Console

للتأكد من ملكية الموقع في Google Search Console، أنشئ خاصية **URL prefix** للعنوان الأساسي النهائي، ويُفضّل تنفيذ ذلك بعد ربط نطاق مخصص. اختر طريقة **HTML tag**، ثم انسخ قيمة `content` فقط من وسم Google وضعها في متغير Vercel باسم `GOOGLE_SITE_VERIFICATION` في بيئتي Production وPreview. سيضيف التطبيق وسم التحقق تلقائيًا عند وجود القيمة. هذه القيمة مرئية أصلًا في HTML لغرض التحقق وليست مفتاح API أو بيانات دخول؛ لا تضف أي مفاتيح Google سرية أو ملفات حساب خدمة إلى Vercel أو Git لهذه الخطوة.

بعد النشر، أرسل خريطة الموقع من Search Console على `/sitemap.xml`، وراقب تقرير الفهرسة قبل الاعتماد على ترتيب أي صفحة أو استنتاجه.

## المسارات الرئيسية

| المسار | الوظيفة |
|---|---|
| `/` | الصفحة الرئيسية والتصنيفات والخدمات |
| `/catalog` | كتالوج الخدمات مع فلترة التصنيفات |
| `/service/[slug]` | تفاصيل الخدمة وحقول الطلب الديناميكية |
| `/account` | منطقة العميل: الرصيد والطلبات والدعم والإعدادات |
| `/admin` | لوحة إدارة ChriGsm CMC |
| `/verify-email` | متابعة تأكيد البريد وإعادة إرسال رابط التفعيل |
| `/auth/action` | معالجة روابط تأكيد البريد وإعادة تعيين كلمة المرور |
| `/terms` | الشروط والأحكام |
| `/privacy` | سياسة الخصوصية |

## قواعد الأمان

تجري عمليات الرصيد والطلبات والدعم والتعديلات الإدارية عبر Route Handlers خادمية بعد التحقق من هوية المستخدم وصلاحيته. لا تستخدم أي قيم Firebase Admin في المتصفح أو في متغيرات تبدأ بـ `NEXT_PUBLIC_`.

## موصل AI الخارجي للمدونة

يدعم CMC مساعد كتابة خارجيًا **لمحتوى المدونة فقط**. ينشئ مخططات ومسودات Markdown واقتراحات عناوين وSEO، ولكنه لا يملك أدوات ولا وصولًا إلى العملاء أو الطلبات أو الدفع أو Firestore، ولا يحفظ أو ينشر أي مقال تلقائيًا. يجب أن يراجع المالك الناتج ويدخله في محرر المقال ثم يحفظه أو ينشره يدويًا.

| المتغير | الغرض |
|---|---|
| `CONTENT_AI_ENABLED` | يبقى `false` إلى أن يكتمل الإعداد والمراجعة. |
| `CONTENT_AI_PROVIDER` | اسم المزود الظاهر للمالك، مثل Gemini أو Spark. |
| `CONTENT_AI_PROTOCOL` | `openai-chat` لمزودي Chat Completions المتوافقين، أو `gemini-generate-content` لواجهة Gemini. |
| `CONTENT_AI_API_URL` | رابط POST الكامل للمزود؛ يجب أن يكون HTTPS. |
| `CONTENT_AI_API_TOKEN` | رمز الوصول السري على الخادم فقط. |
| `CONTENT_AI_MODEL` | اسم النموذج لدى المزود. |
| `CONTENT_AI_ALLOWED_HOSTS` | قائمة بيضاء بأسماء المضيفين المسموحة، مفصولة بفواصل. |
| `CONTENT_AI_INSTRUCTIONS` | تعليمات أسلوب دائمة للكاتب، مع بقاء قواعد العزل الأساسية مفروضة خادميًا. |
| `CONTENT_AI_DAILY_LIMIT` | سقف يومي بين 1 و100 طلب لحماية الاستهلاك. |

> لا تضف `CONTENT_AI_API_TOKEN` إلى أي متغير يبدأ بـ `NEXT_PUBLIC_`، ولا تضعه في Firestore أو Git أو أي حقل ظاهر في CMC. أضف القيم الحقيقية في متغيرات بيئة Vercel للإنتاج والمعاينة، واتركها معطلة محليًا إلى أن تحتاجها.

لا يقبل الموصل إلا رابط HTTPS ينتمي إلى مضيف مدرج في `CONTENT_AI_ALLOWED_HOSTS`. يسجّل النظام كل طلب ناجح في `auditLogs` مع نوع المهمة والمزود والنموذج فقط؛ لا يسجل الرمز السري أو محتوى المقال.
