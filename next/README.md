# ChriGsm — Next.js + Firebase

تطبيق ChriGsm لمتجر الخدمات الرقمية، ومنطقة حساب العميل، ولوحة إدارة CMC. يعتمد المشروع على Next.js للواجهة ومسارات الخادم، وعلى Firebase للمصادقة والبيانات، مع تكامل مهيأ لتخزين الوسائط. تعتمد الواجهة على البيانات التشغيلية المتاحة فقط؛ وعند غياب بيانات الكتالوج تظهر حالات فارغة آمنة بدل أي محتوى افتراضي.

## التطوير والتحقق

شغّل `npm run dev` ثم افتح `http://localhost:3000`. قبل النشر، استخدم `npm run lint` ثم `npm run build` للتحقق من جودة الشيفرة وبناء الإنتاج.

| الأمر | الغرض |
|---|---|
| `npm run dev` | تشغيل معاينة محلية مع التحديث الفوري |
| `npm run lint` | فحص جودة الشيفرة |
| `npm run build` | تحقق من بناء الإنتاج |
| `npm run emulators` | تشغيل محاكيات Firebase محليًا عند الحاجة |
| `npm run test:firestore-rules` | اختبار قواعد Firestore محليًا |

## الإعداد

انسخ `.env.example` إلى `.env.local` وأضف قيم تطبيق Firebase العامة وقيم Firebase Admin الخادمية. لا ترفع ملف `.env.local` أو مفتاح الخدمة إلى Git. انشر `firestore.rules` و`storage.rules` من Firebase CLI بعد مراجعة القواعد.

يجب أن يشير `NEXT_PUBLIC_APP_URL` إلى عنوان HTTPS العام للتطبيق، لأنه يستخدم لإنشاء روابط ChriGsm المخصصة لتأكيد البريد الإلكتروني وإعادة تعيين كلمة المرور.

## المسارات الرئيسية

| المسار | الوظيفة |
|---|---|
| `/` | الصفحة الرئيسية والتصنيفات والخدمات |
| `/catalog` | كتالوج الخدمات مع فلترة التصنيفات |
| `/service/[slug]` | تفاصيل الخدمة وحقول الطلب الديناميكية |
| `/account` | منطقة العميل: الرصيد والطلبات والدعم والإعدادات |
| `/admin` | لوحة إدارة ChriGsm CMC |
| `/verify-email` | متابعة تأكيد البريد وإعادة إرسال رابط التفعيل |
| `/auth/action` | معالجة روابط تأكيد البريد وإعادة تعيين كلمة المرور |
| `/terms` | الشروط والأحكام |
| `/privacy` | سياسة الخصوصية |

## قواعد الأمان

تجري عمليات الرصيد والطلبات والدعم والتعديلات الإدارية عبر Route Handlers خادمية بعد التحقق من هوية المستخدم وصلاحيته. لا تستخدم أي قيم Firebase Admin في المتصفح أو في متغيرات تبدأ بـ `NEXT_PUBLIC_`.
