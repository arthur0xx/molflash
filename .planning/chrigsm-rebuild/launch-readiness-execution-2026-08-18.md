## فحص الكتالوج العام

فُتحت صفحة `/catalog` على النطاق الثابت. ظهرت واجهة RTL سليمة، حقل بحث واضح، و28 بطاقة خدمة قابلة للنقر. ظهرت خدمات Borneo وREFOX وCheetah وEFT Pro وHydra وChimera وE-GSM وUnlock Tool وZhizhen وAMT مع أسعارها ومدة الخدمة. لم يظهر خطأ بصري أو رابط ظاهر مكسور في فحص الصفحة العامة.

## قرار التنفيذ التالي

الفجوة الوظيفية الأوضح خارج الدفع والمصادقة هي أن CMC يدعم حاليًا مدير طلبات ومدير دعم فقط، بينما متطلب المتجر يتضمن مدير كتالوج محدودًا بلا وصول إلى العملاء أو المحافظ أو الدفع. سيتم تقييم وتنفيذ أقل صلاحية خادمية وواجهة لازمة لهذا الدور، مع الحفاظ على أن ضبط السعر والتفعيل ومسارات الشراء الخاصة تظل ملكًا للمالك فقط.

## مدير الكتالوج المحدود

أضيفت صلاحية `catalog` إلى Custom Claims للمشرفين، مع اختيار دور واحد فقط عند إنشاء الحساب: مدير طلبات أو مدير دعم أو مدير كتالوج. يستلم مدير الكتالوج لقطة CMC خادمية تحتوي التصنيفات والخدمات فقط؛ لا تصل إليه وثائق العملاء أو الطلبات أو المحافظ أو وسائل الدفع أو عمليات التحويل.

يمكن لمدير الكتالوج إعداد مسودات الخدمات والتصنيفات وتعديل وصف الخدمة وحقول الطلب وصورتها وتبعيتها. تبقى الأسعار والسعر قبل التخفيض وإتاحة الخدمة للعملاء وإبرازها في الكتالوج والحذف وروابط شراء المورد داخلية للمالك فقط. ينفذ الخادم هذه الحدود على المسارات نفسها، وليس بالواجهة فقط. كما يبقى وصول Firebase SDK المباشر للمدير مرفوضًا بقواعد Firestore.

### معاينة Vercel

نُشرت معاينة الالتزام `f81431d` على `https://chrigsm-next-pc27irbd0-arthurs-projects-713d8d1f.vercel.app` بحالة Ready. فحصت الصفحة العامة وعرضت الكتالوج والصور والروابط دون عطل ظاهر. كما فُتح `/admin` كزائر وأظهر حالة «لوحة CMC محمية» مع رابط تسجيل الدخول فقط، ولم يعرض أي عميل أو طلب أو محفظة أو وسيلة دفع.

لا يمكن اختبار مسار مدير الكتالوج الحي من دون إنشاء حساب فريق فعلي بكلمة مرور مؤقتة؛ لم يُنشأ حساب جديد تلقائيًا حفاظًا على عدم إدخال هوية أو بيانات اعتماد تشغيلية غير مطلوبة.

### تحقق حواجز API داخل المعاينة

ضمن جلسة معاينة Vercel، استدعيت مسارات التطبيق دون رمز Firebase. أعاد `/api/admin/snapshot` الحالة `403` مع رسالة «غير مصرح»، كما أعاد كل من `/api/admin/categories` و`/api/admin/media/signature` الحالة `403`. يؤكد ذلك أن حماية المسارات تستمر داخل التطبيق بعد تجاوز حماية معاينة Vercel، وأن التوسعة لا تفتح بيانات الكتالوج أو توقيعات Cloudinary للزائر.

## فحص الإصدار والمراقبة الأساسية

أضيف أمر قابل للتكرار:

```bash
npm run check:release -- https://temporary-speedy-jade-mdelya8.vercel.app
```

يفحص الأمر الصفحة الرئيسية والكتالوج و`robots.txt` و`sitemap.xml` ومسار CMC، ثم يتحقق أن `/api/admin/snapshot` يرفض الزائر. اجتاز النطاق الثابت الحالي جميع هذه الفحوصات، ومنها حاجز API بالحالة `403`.

فحص `npm audit --omit=dev --audit-level=high` لم يعثر على ثغرات عالية أو حرجة. بقيت ست ثغرات **متوسطة** موروثة عبر `firebase-admin` و`@google-cloud/storage` وسلسلة `uuid`. لم يطبق `npm audit fix --force` لأنه يقترح خفض `firebase-admin` إلى إصدار كاسر (`10.3.0`)، وهو غير آمن تلقائيًا قبل اختبار توافق منفصل.
