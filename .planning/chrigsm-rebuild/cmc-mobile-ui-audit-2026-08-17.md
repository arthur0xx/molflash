# تدقيق واجهة CMC على الهاتف — 2026-08-17

## مصدر الملاحظة

لقطات شاشة قدّمها المالك من صفحة CMC على هاتف Android بعرض يقارب 1080px. تُظهر اللقطات نافذة إضافة/تعديل خدمة أو تصنيف، لوح العملاء، ولوح الطلبات.

## العيوب الحرجة المرصودة

| المنطقة | العيب المرئي | الأثر على الاستخدام | أولوية الإصلاح |
|---|---|---|---|
| نوافذ إضافة/تعديل الخدمة والتصنيف | شبكة سطح مكتب ذات أعمدة متعددة بقيت أفقية داخل نافذة هاتف ضيقة، فتقطع النصوص والحقول وتنتج تمريرًا أفقيًا غير مفهوم | لا يستطيع المالك رؤية الحقول أو تعديلها بثقة | حرجة |
| نافذة الخدمة | أقسام «نموذج الطلب» و«رابط شراء الخدمة» طويلة ومتصادمة داخل النافذة؛ شريط الأزرار في الأسفل ليس مثبتًا ضمن مساحة آمنة | حفظ التعديل أو إلغاؤه يحتاج تمريرًا طويلًا وقد يؤدي إلى أخطاء | حرجة |

| لوح الطلبات | أزرار التصفية تتكسر إلى صفوف صغيرة ومحتوى بطاقة الطلب كثيف | قراءة الحالة وإدارة الطلب بطيئة على الهاتف | عالية |
| الواجهة العامة | أحجام النصوص والفواصل غير منضبطة بسبب تراكب قواعد CSS ومراحل تصميم مختلفة | مظهر غير مكتمل لا يطابق مستوى متجر احترافي | عالية |

## قرار التصميم

يتحول CMC إلى نمط **تطبيق إدارة عربي mobile-first**: شريط علوي موجز، تنقل سفلي للهاتف لا يتجاوز خمس وجهات أساسية مع «المزيد»، بطاقات مركزة، صفحات تفاصيل أو sheets كاملة الارتفاع بدل نافذة ضيقة متعددة الأعمدة، وشريط إجراءات سفلي ثابت داخل كل شاشة تعديل. لا تستخدم الأعمدة المتعددة قبل حد سطح المكتب؛ كل نموذج هاتف يكون عمودًا واحدًا وتسلسلًا مرحليًا عند الحاجة.

## معايير القبول

1. لا يوجد تمرير أفقي عند عرض 360px و390px و430px.
2. كل هدف لمس لا يقل عن 44px، والحفظ أو الإلغاء يبقيان ظاهرين داخل المساحة الآمنة.
3. حقول إضافة/تعديل الخدمة تظهر كصفحة أو sheet بعمود واحد على الهاتف، مع أقسام قابلة للطي.
4. إجراءات العميل الحساسة تُفصل عن تعديل الرصيد ولا تُعرض في نفس المنطقة الأولى.
5. لوحة السطح المكتبي تحتفظ بكثافة أعلى ضمن شبكة واضحة دون التأثير على الهاتف.
6. تحترم الحركة تفضيل تقليل الحركة، وتستخدم فقط لتأكيد الانتقال أو الحفظ أو ظهور الورقة.

## ملاحظات تقنية

- `src/app/globals.css` يحتوي على تعريفات متكررة ومتصادمة لـ `.cmc-sidebar` و`.cmc-content` و`.editor-dialog` و`.dialog-backdrop` وقواعد الهاتف، وهو السبب الأولي للتخطيط الهش.
- `src/components/admin-console.tsx` مركب كبير؛ يجب فصل محرر الخدمة وإدارة العملاء وبطاقات الطلبات إلى مكونات واضحة قبل إعادة تصميمها.
- لا تُغير مسارات API أو الصلاحيات أو منطق الأسعار خلال مرحلة واجهة المستخدم.

## نتيجة اختبار الهاتف الفعلي

جرى فتح صفحة CMC الإنتاجية في جلسة إدارة صالحة بمحاكاة جهاز بعرض CSS قدره 390px وارتفاع 844px مع لمس مفعّل. أعادت الصفحة `innerWidth: 390` و`scrollWidth: 390`، أي لا يوجد تجاوز أفقي. تُظهر اللقطة الناتجة شبكة ملخصات ثنائية مفهومة، وبطاقة طابور عمل واحدة، وتنقّل CMC سفليًا بخمس وجهات فقط. ملف التحقق البصري محفوظ في `cmc-mobile-production-390.png`.

لم يُجرَ حفظ أو إنشاء أو حذف أي تصنيف أو خدمة أثناء الفحص. اختبار فتح محرر التصنيف عبر أداة المحاكاة الثانوية لم يعطِ شجرة أزرار يمكن التحكم بها داخل تبويب الاختبار، لذلك اقتصر التحقق النهائي لهذه النافذة على البناء الناجح وقواعد CSS المطبقة على جميع شاشات اللمس. سيُعاد التحقق التفاعلي من المحرر خلال أول دورة CMC فعلية على الهاتف.

اختبار القياسات الإضافي أعطى نتائج سليمة: `320/320` للهاتف الصغير، و`768/768` للوحـي، و`1425 ≤ 1440` للسطح المكتبي؛ الرقم الأول هو عرض المحتوى القابل للتمرير والثاني عرض viewport. لم يظهر تجاوز أفقي في أي قياس. كما لم يعثر فحص Vercel على أخطاء وقت تشغيل ضمن الساعة التالية للترقية.
