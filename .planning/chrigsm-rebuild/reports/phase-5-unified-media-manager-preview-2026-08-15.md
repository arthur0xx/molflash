# تقرير مدير الأصول الموحد — معاينة

- **التاريخ:** 2026-08-15 GMT+1
- **الفرع:** `rebuild/next-firebase`
- **النطاق:** تحسين غير مدمر لمسار الصور الحالي؛ لا تغيير في حسابات الاختبار أو بيانات Firebase أو أصول Cloudinary الحية.

## التغيير المنفذ

أضيفت وحدة عميل مشتركة في `next/src/lib/media-upload.ts` للتحقق من نوع/حجم الصورة، طلب توقيع خادمي قصير العمر، والرفع المباشر إلى Cloudinary مع مهلة واضحة. استبدل CMC منطق رفع صور الخدمات المكرر بهذه الوحدة. أضيف خيار صورة الحساب إلى إعدادات العميل باستخدام مسار التوقيع الموجود `/api/account/media/signature` ومسار الحفظ المدقق `/api/account/profile`.

صُحح عقد صور الخدمات ليقبل البنية الحالية للرفع `chrigsm/catalog/{category}/{name-id}` إلى جانب البنية القديمة المتوافقة `chrigsm/services/{id}`. يبقى حفظ الرابط ومعرف الأصل عبر مسارات خادمية ومدققًا في `auditLogs`، بينما يحذف الأصل القديم فقط بعد حفظ المرجع الجديد بنجاح.

## نتائج البوابات

| البوابة | النتيجة |
|---|---|
| `npm run lint` | نجح بلا أخطاء؛ توجد تحذيرات موجودة مسبقًا عن صور `<img>` ومتغيرات غير مستخدمة. |
| `npm run build` | نجح. |
| `npm run test:firestore-rules` | نجح؛ ثبت منع كتابات العميل المباشرة وعزل الزائر والعميل المحظور. |
| زائر: `GET /api/admin/media/signature` | `403` كما هو مطلوب. |
| زائر: `GET /api/account/media/signature` | `403` كما هو مطلوب. |
| رابط الإنتاج: `/account` للزائر | حمّل بنجاح وطلب تسجيل الدخول. |

## حدود الاختبار

لم تُرفع صورة حقيقية ولم يُحذف أصل حي خلال هذه البوابة. يتطلب اختبار الرفع الكامل حساب مدير أو عميل موثقًا مع Cloudinary المهيأ في بيئة المعاينة. ظهر خطأ محلي في Turbopack متعلق بملف `favicon.ico` المضاف في التحديثات اليدوية، لكن بناء الإنتاج نجح وصفحة الحساب المنشورة تعمل؛ لذلك لا ينسب هذا العائق إلى مدير الأصول.

## القرار التالي

تثبيت الشيفرة والوثائق محليًا، نشر معاينة Vercel، ثم التحقق من صفحات الدخول والحساب ومسارات توقيع الزائر. لا ترقية للإنتاج قبل نجاح المعاينة.
