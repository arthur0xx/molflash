## بوابات التحقق

| البوابة | النتيجة | الدليل |
|---|---|---|
| البناء | ناجح | `npm run build` اكتمل بنجاح بعد تدفق الاستعادة. |
| قواعد Firebase | ناجح | `npm run test:firestore-rules` اجتاز عزل الزائر والعميل والدعم ومنع الكتابات المباشرة. |
| الزائر | ناجح | ظهر رابط «نسيت كلمة المرور؟»، ونجح اختبار بريد محجوز وغير موجود برسالة عامة لا تكشف وجود الحساب. |
| العميل | ناجح | ظهر زر «إرسال رابط التغيير» العامل في حساب العميل، واستهدف تصميمه بريد جلسة Firebase فقط؛ لم يُرسل بريد فعلي وفق حدود التشغيل. |
| المدير | ناجح | بقي حساب العميل محجوبًا عن `/admin`، ولم يمس التغيير Custom Claims أو مسارات الإدارة. |
| العزل | ناجح | لا تقرأ الاستعادة Firestore ولا تعدّل وثائق عميل أو دورًا أو رصيدًا؛ استمرت اختبارات القواعد. |
| المعاينة | ناجح | صفحة `/login` ومود الاستعادة ورسالة الخصوصية، مع حماية `/account` و`/admin` للزائر. |
| الإنتاج | ناجح | ظهر نموذج الاستعادة ورسالة الخصوصية على الرابط الدائم، وبقيت الرؤوس والمسارات المحمية سليمة. |

## إعداد Firebase وVercel

أضيف النطاق الثابت `temporary-speedy-jade-mdelya8.vercel.app` إلى Authorized Domains في Firebase Authentication. وأضيف `NEXT_PUBLIC_APP_URL` بالقيمة HTTPS نفسها في بيئتي Vercel Production وPreview وفي نموذج البيئة المحلي. بقي Email/Password مفعّلًا. حاولت مراجعة قالب إعادة التعيين، إلا أن Firebase Console أعلن أن تحديثات القوالب غير متاحة حاليًا للمشروع؛ لا يمنع ذلك إرسال Firebase للرابط الآمن أو عودته إلى النطاق المسموح، لكنه يمنع ادعاء تخصيص القالب العربي.

## التالي أو العائق

اجتازت المعاينة والإنتاج رابط `/login` ومود الاستعادة واختبار البريد المحجوز ورسالة الخصوصية. أكد الرابط الدائم أيضًا CSP والرؤوس الدفاعية، وأعاد API الإداري `403` للزائر. لم يُرسل رابط استعادة إلى حساب حقيقي أثناء الفحص، التزامًا بعدم إرسال بريد فعلي. المهمة التالية هي استكمال مراجعة الإطلاق والتوثيق، مع إبقاء قالب Firebase الافتراضي حتى تتاح تعديلات القوالب للمشروع.
