# دليل النسخ الانتقالي بلا فوترة — ChriGsm

**الحالة:** خطة تشغيل انتقالية؛ لا يوجد حاليًا نسخ Firestore تلقائي أو ملف نسخة معتمد.  
**الغرض:** منع ادعاء حماية غير موجودة أثناء بيتا محدودة، وتحديد ما يلزم قبل إنشاء أول نسخة يدوية قابلة للتحقق.  
**خارج النطاق:** لا يفعّل هذا الدليل Blaze أو Cloud Storage أو Firebase Storage أو أي خدمة مدفوعة.

## 1. نطاق الحماية

لا تكفي نسخة Firestore وحدها لاستعادة المنصة. يحمي كل أصل بمسار منفصل، ولا تجمع الأسرار أو كلمات المرور داخل ملف نسخة.

| الأصل | النطاق | أسلوب الحماية الانتقالي | لا يتضمن |
|---|---|---|---|
| Firestore | `categories` و`services` و`customers` و`orders` و`walletEntries` و`supportTickets` و`auditLogs` | لقطة JSON قراءة فقط، تحفظ خارج المستودع بعد التحقق. | مفاتيح Firebase أو كلمات المرور. |
| Firebase Authentication | مستخدمو Email/Password وCustom Claims | جرد يدوي آمن للحسابات والإجراءات، من دون تصدير أو حفظ كلمات المرور. | كلمات المرور أو رموز الجلسات. |
| Cloudinary | أصول الصور وسجلاتها | مراجعة قائمة الأصول أو تصدير خاص من Cloudinary يملكه المالك. | API secret أو روابط عامة للنسخ. |
| التطبيق والتكوين | `rebuild/next-firebase`، قواعد Firestore، ملفات المشروع ووثائق البيئة | GitHub وVercel ومراجعة مكتوبة للمتغيرات المطلوبة. | قيم المتغيرات الحساسة نفسها. |

> لا تضع ملف نسخة في Git، أو Cloudinary، أو مجلد تنزيل عام، أو مرفق محادثة. لا تحفظ Firebase Admin private key أو Cloudinary API secret أو كلمات مرور المستخدمين ضمن JSON أو manifest.

## 2. شرط التنفيذ قبل أول نسخة

لا يعد هذا الدليل تنفيذًا للنسخ. قبل إنتاج أول لقطة، يلزم تنفيذ سكربت قراءة فقط ومراجعته، أو اختيار النسخ المدارة على Blaze. يجب أن يحقق السكربت المتطلبات التالية:

| المطلب | قاعدة القبول |
|---|---|
| هوية الخادم | يستعمل Firebase Admin من بيئة موثوقة موجودة أصلًا، ولا يطبع أي متغير أو مفتاح. |
| القراءة فقط | لا ينفذ `set` أو `update` أو `delete`، ولا يستدعي أي مسار CMC. |
| نطاق ثابت | يقرأ المجموعات السبع المذكورة في هذا الدليل فقط، ما لم يراجع المالك نطاقًا جديدًا. |
| مكان الخرج | يكتب خارج المستودع؛ المثال المسموح محليًا هو `backups/chrigsm-YYYY-MM-DD.json` في مسار خاص غير متعقب. |
| manifest | يسجل وقت التصدير، إصدار Git، مشروع Firestore، عدد الوثائق لكل مجموعة، وSHA-256 للملف. |
| تحقق | يفحص المخطط والـSHA-256 والأعداد قبل وصف النسخة بأنها صالحة. |
| اختبار استعادة | يقرأ النسخة في Firebase Emulator فقط. لا يكتب إلى Firestore الإنتاج ولا ينشئ قاعدة جديدة. |

## 3. تسلسل اللقطة اليدوية عند تفعيلها

ينفذ المالك أو مشغل موثوق الخطوات بالتسلسل. إذا فشلت أي بوابة، لا تسمى النتيجة نسخة احتياطية ولا تحذف أي ملف أقدم.

| الترتيب | العملية | دليل النجاح |
|---|---|---|
| 1 | تأكيد أن النسخة بيتا محدودة، وأن الإجراء لا يتضمن Blaze أو Cloud Storage. | لا توجد تغييرات فوترة أو تخزين. |
| 2 | قراءة حالة Git وإصدار التطبيق؛ تأكيد أن متغيرات Firebase متاحة محليًا فقط. | يسجل manifest الالتزام وليس أي سر. |
| 3 | تشغيل تصدير القراءة فقط إلى موقع خاص خارج Git. | ملف JSON جديد بحجم غير صفري. |
| 4 | إنشاء manifest وSHA-256، ثم فحص عدد الوثائق لكل مجموعة. | لا تظهر مفاتيح أو كلمات مرور أو مخرجات خطأ ضمن الملف. |
| 5 | تشغيل أداة تحقق مستقلة تقرأ اللقطة دون تعديلها. | نجاح المخطط والـhash والأعداد. |
| 6 | إجراء اختبار استعادة إلى Firebase Emulator عند أول نسخة ثم دوريًا. | تقرأ المجموعات المطلوبة في Emulator من دون اتصال أو كتابة إلى الإنتاج. |
| 7 | تشفير الملف خارج المستودع بمفتاح يملكه المالك، أو وضعه في مساحة خاصة يسيطر عليها المالك. | لا تصبح النسخة أو manifest عامين. |

## 4. تكرار النسخ وحدود الاستعادة

خلال بيتا محدودة، يكون الحد الأدنى العملي لقطة أسبوعية، مع لقطة إضافية قبل أي تعديل CMC كبير أو بعد تغيير حقيقي في الخدمات. لا يستخدم تشغيل مجدول داخل sandbox مؤقت أو جهاز محلي لإيهام وجود نسخ تلقائية.

لا تحمي الخطة الانتقالية من فقدان بيانات بين نسختين، ولا تستعيد Firebase Authentication أو أصول Cloudinary أو كلمات المرور. عند إدخال طلبات تجارية أو بيانات عملاء حقيقية مستمرة، يتحول القرار إلى النسخ المدارة على Blaze مع ميزانية وتنبيهات؛ تتطلب النسخ المدارة Blaze وتخزينًا مدفوعًا، وتستعيد البيانات إلى قاعدة Firestore جديدة لا إلى القاعدة القائمة. [1] [2]

## 5. اختبار الاستعادة الآمن

ينفذ اختبار الاستعادة في Emulator فقط للخطة الانتقالية. يثبت الاختبار أن ملف JSON قابل للقراءة، وأن كل مجموعة مطلوبة موجودة، وأن عدد الوثائق يطابق manifest، وأن نماذج الخدمات والطلبات وقيود المحفظة وسجل التدقيق تقرأ كما يتوقع التطبيق. لا تتصل عملية الاختبار بإنتاج Firebase، ولا تحذف أي قاعدة أو وثيقة.

إذا اختار المالك النسخ المدارة مستقبلًا، يكون اختبار الاستعادة إلى **قاعدة جديدة** مخصصة للتدريب، ثم تراجع قواعد IAM وTTL يدويًا؛ لا توجه بيئة الإنتاج إلى قاعدة الاستعادة خلال الاختبار. [1]

## 7. قرار مطلوب

يتطلب الإطلاق التجاري قرار المالك بين استمرار بيتا محدودة مع النسخ اليدوي الانتقالي، أو تفعيل Blaze واعتماد النسخ المدارة مع ميزانية وتنبيهات. لا ينفذ هذا القرار تلقائيًا بسبب قيد المشروع الصريح: **لا فوترة**.
