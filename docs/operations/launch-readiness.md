# دليل جاهزية إطلاق ChriGsm

**الحالة:** بيتا تشغيلية؛ ليست جاهزة بعد لإطلاق عام مفتوح.  
**النطاق:** متجر ChriGsm، CMC، منطقة العميل، Firebase Authentication وFirestore، وVercel.  
**تاريخ المراجعة:** 14 أغسطس 2026 بتوقيت Africa/Casablanca.

هذا الدليل يفصل بين ما هو منشور ويعمل فعليًا، وما يتطلب قرارًا أو إجراءً يدويًا من مالك المشروع. لا يفعّل هذا الدليل فوترة أو تخزين Firebase أو دفعًا أو رسائل WhatsApp، ولا يحذف حسابات أو بيانات.

## 1. الحالة التشغيلية المثبتة

| المجال | الحالة | الدليل التشغيلي |
|---|---|---|
| متجر الخدمات والكتالوج | منشور | المنتجات والتصنيفات والأسعار تأتي من Firestore؛ لا يوجد دفع أو تحصيل آلي. |
| CMC | منشور ومحمي | إدارة الخدمات والتصنيفات والطلبات والمحافظ والدعم تمر بمسارات خادمية متحققة من Firebase ID Token وCustom Claims. |
| منطقة العميل | منشورة ومحميّة | العميل لا يرى إلا حسابه وطلباته وتذاكره المصرح بها بواسطة قواعد Firestore. |
| تسجيل الدخول | منشور | يعتمد Firebase Email/Password فقط؛ لا توجد بيانات اعتماد أو أزرار تعبئة تجريبية في الواجهة. |
| استعادة كلمة المرور | منشورة | الصفحة العامة والحساب يرسلان طلب Firebase برسالة واجهة عامة لا تعدّد الحسابات، ويستعملان نطاق الإنتاج المعتمد. |
| الرؤوس الدفاعية | منشورة | CSP و`X-Frame-Options: DENY` و`X-Content-Type-Options: nosniff` وسياسات الإحالة/الصلاحيات موجودة؛ لا يظهر `X-Powered-By`. |
| الصور | منشورة ضمن Cloudinary | لا يعتمد التطبيق على Firebase Storage أو فوترة Firebase Storage. |
| النسخ الاحتياطي | غير منفذ بعد | لا يوجد جدول نسخ أو ملف نسخة تشغيلية أو اختبار استعادة معتمد حتى الآن. |

> لا يعني ظهور ميزة الاستعادة في الواجهة أن قالب بريد Firebase أصبح مخصصًا عربيًا. تدفق Firebase صالح، لكن حفظ تعديل قالب البريد في Console لم يكن متاحًا أثناء المراجعة.

## 2. بوابة الإطلاق العام

لا يعلن الموقع إطلاقًا عامًا قبل إغلاق كل صف في الجدول التالي. أي عنصر ذي مالك خارجي لا يُنفذ تلقائيًا ولا يُتجاوز بتغيير نص في الواجهة.

| الشرط | المالك | الحالة الحالية | الإجراء المطلوب للإغلاق |
|---|---|---|---|
| حسابات اختبار Firebase | مالك مشروع Firebase | مفتوحة لأغراض التحقق السابقة | اختر **تعطيلًا** مؤقتًا أو **حذفًا** نهائيًا بعد مراجعة ارتباطها بوثائق Firestore التجريبية؛ لا تحذف حسابًا أو وثيقة اعتمادًا على الاسم فقط. |
| كلمات مرور الاختبار | مالك مشروع Firebase | لا تظهر في الواجهة أو Git | إن بقي حساب اختبار لأي سبب، غيّر كلمة مروره إلى قيمة لا تُشارك ولا تستخدمه كحساب عام. |
| بيانات Firestore التجريبية | مالك المشروع مع مراجعة CMC | موجودة لأغراض الاختبار | راجع كل وثيقة قبل الحذف. لا ينفذ التنظيف الآلي لأن الطلبات أو سجلات التدقيق قد تكون لازمة للتحقق أو للمراجعة. |
| عنوان المرسل وقالب الاستعادة | مالك مشروع Firebase | قالب Firebase الافتراضي فقط | نفّذ اختبارًا يدويًا بحساب مملوك للمالك بعد أن تسمح Console بالتعديل، ثم اعتمد الاسم واللغة والنص أو أبق القالب الافتراضي صراحة. |
| نطاق عام مخصص | مالك Vercel/DNS | يستخدم نطاق Vercel الثابت | عند إضافة نطاق مخصص، أضفه إلى Firebase Authorized Domains، حدّث `NEXT_PUBLIC_APP_URL` في Vercel Preview وProduction، ثم اختبر الاستعادة قبل تحويل أي زيارات عامة. |
| النسخ الاحتياطي | مالك المشروع | لا توجد نسخة معتمدة | نفذ مسار النسخ الانتقالي في [دليل النسخ](./backup-runbook.md)، أو وافق صراحة على Blaze والنسخ المدارة قبل الإطلاق التجاري. |
| مراجعة الالتزام البعيد | مالك GitHub أو صاحب رمز وصول صالح | توجد التزامات محلية من إعادة البناء لم تُدفع بعد | استعد رمز GitHub صالحًا ثم ادفع `rebuild/next-firebase` فقط؛ لا تدمج `main` ضمن هذا الإجراء. |

## 3. إجراء المالك لحسابات الاختبار

يُنفذ هذا الإجراء يدويًا داخل Firebase Console بعد مراجعة البيانات، وليس من واجهة المتجر أو من تشغيل مجدول. الهدف هو منع بقاء أي حساب تجريبي معروف أو كلمة مرور اختبار صالحة عند فتح التسجيل العام.

| الخطوة | الإجراء الآمن | نتيجة التحقق |
|---|---|---|
| 1 | افتح Firebase Authentication ثم Users، وحدد الحسابات التي أنشئت للتجارب فقط بالرجوع إلى سجل الإنشاء وFirestore. | قائمة مراجعة داخلية لا تتضمن كلمات مرور. |
| 2 | راجع في Firestore الوثائق والطلبات وقيود المحفظة والتذاكر المرتبطة بكل حساب. | لا تُمس بيانات حقيقية أو سجل مطلوب للتدقيق. |
| 3 | للاختبار القصير المتبقي، عطّل الحساب بدل حذفه. وللتنظيف النهائي، احذف الحساب فقط بعد اعتماد قائمة المالك. | لا يعود الحساب قادرًا على الدخول. |
| 4 | إن حُذف الحساب، عالج وثائقه المرتبطة وفق سياسة احتفاظ مكتوبة؛ لا تفترض أن حذف Firebase Auth يحذف Firestore تلقائيًا. | لا تبقى وثائق يتيمة غير مقصودة. |
| 5 | افتح `/login` كزائر وتأكد أن الواجهة لا تحتوي بريد اختبار أو كلمة مرور أو زر تعبئة. | اجتياز بوابة الواجهة العامة. |

تدعم واجهة Firebase Admin إدارة المستخدمين وتعطيلهم أو حذفهم، لكنها قدرة مرتفعة الصلاحية ويجب استعمالها من بيئة خادمية موثوقة فقط، لا من المتصفح. [1]

## 4. استعادة كلمة المرور والنطاق

يستخدم التطبيق `sendPasswordResetEmail` مع `ActionCodeSettings` ورابط عودة ثابت إلى صفحة الدخول. الرسالة التي يراها الزائر عامة عمدًا: نجاحها لا يثبت أن البريد مسجل، وبالتالي لا تسمح بتعداد الحسابات. لا تطبع الواجهة رابط Firebase أو رمز الاستعادة أو عنوان البريد المستهدف.

عند توفر نطاق مخصص لاحقًا، يبقى ترتيب التغيير إلزاميًا: إضافة النطاق إلى Authorized Domains، تحديث متغير Vercel العام في Preview وProduction، نشر معاينة، اختبار رابط الاستعادة على النطاق الجديد بحساب يملكه المالك، ثم الترقية. يمكن لـFirebase استخدام رابط متابعة ضمن `ActionCodeSettings`، بينما يتطلب أي معالج بريد مخصص صفحة آمنة تتحقق من رمز العملية وتنفذ إعادة التعيين؛ لا توجد هذه الصفحة المخصصة في ChriGsm حاليًا. [2]

## 5. النسخ الاحتياطي والقرار المالي

الخطة الحالية **لا فوترة**. لذلك لا يوجد نسخ Firestore مجدول ولا ادعاء بوجود استعادة تلقائية. النسخ الانتقالي اليدوي الموثق في [دليل النسخ](./backup-runbook.md) مناسب فقط لبيتا محدودة وبيانات قليلة، ويجب أن يبقى خارج Git وخارج Cloudinary وأي رابط عام.

قبل إطلاق تجاري أو إدخال طلبات وبيانات أعمال حقيقية بشكل مستمر، يعتمد المالك الخيار التالي صراحة:

| المسار | القرار | أثره |
|---|---|---|
| A — انتقال بلا فوترة | تشغيل نسخة يدوية موثقة والتحقق منها داخل Firebase Emulator. | يقلل الخطر لكنه ليس نسخًا تلقائيًا ولا يحقق نقطة استعادة بين نسختين. |
| B — نسخ Firestore مدارة | تفعيل Blaze، وضع ميزانية وتنبيهات، ثم جدول يومي واحتفاظ متفق عليه واختبار استعادة إلى قاعدة جديدة. | النسخ المدارة تتطلب Blaze وتفرض رسوم تخزين واستعادة؛ الاستعادة تنشئ قاعدة جديدة. [3] [4] |

## 6. قرار الانتقال إلى المرحلة 7

تنتقل المرحلة 7 — الإطلاق والتوثيق — بعد أن يختار المالك وضع حسابات الاختبار وخطة النسخ. يبقى قالب البريد الافتراضي قيدًا موثقًا، لا عطلًا وظيفيًا. أما إطلاق عام مفتوح فيبقى محجوبًا حتى يراجع المالك الحسابات التجريبية ويعتمد مسار النسخ الاحتياطي المناسب.
