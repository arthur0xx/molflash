# ChriGsm CMC — نموذج التشغيل والإدارة

## الهدف التشغيلي

تمنح لوحة CMC المسؤول سيطرة كاملة على الكتالوج والطلبات والعملاء والأرصدة والمراسلات، مع إبقاء منطقة العميل بسيطة وواضحة. كل تغيير إداري مهم يجب أن يسجل المسؤول والوقت والسبب، وخاصة تعديل الرصيد، تغيير حالة الطلب، إرسال كود، حذف منتج، وحذف حساب.

## حالات الطلب

| الحالة | المعنى | الإجراء التالي المعتاد |
|---|---|---|
| جديد | الدفع/الطلب وصل وينتظر المراجعة | إسناد لمعالج أو طلب معلومات |
| بانتظار معلومات العميل | حقل مطلوب ناقص أو معلومة غير صحيحة | إشعار العميل وفتح WhatsApp المرتبط بالطلب |
| قيد المعالجة | بدأ الفريق التنفيذ | تحديث العميل عند الحاجة وتسجيل الملاحظات |
| جاهز للتسليم | توجد نتيجة أو كود أو بيانات خدمة | إرسال الكود أو رابط التسليم ثم تأكيد الحالة |
| مكتمل | تم التسليم بنجاح | أرشفة وإتاحة التقييم أو الدعم اللاحق |
| مرفوض | لا يمكن تنفيذ الطلب | توثيق السبب وقرار الرصيد/الاسترداد |
| ملغى | أُلغي قبل المعالجة أو بطلب العميل | توثيق المبرر وتحديث الرصيد عند اللزوم |

## باني الحقول الديناميكية

يمكن لكل منتج أن يحدد المعلومات المطلوبة من العميل، وتظهر فقط بعد اختيار المنتج أو الباقة. يدعم الباني: نص قصير، نص طويل، بريد إلكتروني، رقم هاتف، اسم كامل، اسم مستخدم، اختيار من قائمة، checkbox للموافقة، رابط، وملف عند إضافة التخزين لاحقًا. كل حقل يحتوي على عنوان ظاهر، اسم داخلي، مثال إدخال، شرط إلزام، شرح، والتحقق من الصيغة.

> مثال All Tool: حقل «البريد الإلكتروني الحالي» اختياري، وخيار «أحتاج بريدًا جديدًا»؛ عند تفعيله يظهر حقل «الاسم الكامل» و«البلد» لإنشاء الحساب. مثال Boronio: «الاسم الكامل» مطلوب، وبعد المعالجة يسجل المسؤول كود التفعيل في رسالة تسليم الطلب ويُرسل إلى العميل من داخل الطلب.

## WhatsApp Business

واجهة الإدارة تستعمل WhatsApp كقناة مرتبطة بالعميل والطلب، لا كبديل غير منظم لسجل الطلبات. كل محادثة تبيّن رقم الهاتف واسم العميل والطلب الحالي والحالة. يوجد زر «إرسال تحديث» في مراحل قيد المعالجة وبانتظار المعلومات وجاهز للتسليم، مع قوالب مختصرة قابلة للتخصيص. منطقة العميل تعرض زر دعم WhatsApp عام وزرًا خاصًا لكل طلب.

لتشغيل الاتصال فعليًا لاحقًا، يلزم ربط WhatsApp Business Platform بخادم الموقع. المتطلبات هي رقم أعمال موثق، Phone Number ID، Access Token يُحفظ على الخادم فقط، Webhook لاستقبال الرسائل وتغييرات الحالة، وقوالب رسائل تمت الموافقة عليها للرسائل خارج فترة المحادثة. لا يوضع الرمز أو بيانات Meta في واجهة العميل أو في مستودع عام.
