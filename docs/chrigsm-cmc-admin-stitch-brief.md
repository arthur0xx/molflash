# ChriGsm CMC — موجز تصميم لوحة الإدارة ومنطقة العميل

## الهدف

تصميم تجربة إدارة رقمية كاملة لمتجر ChriGsm بأسلوب CMC: واجهة سطح مكتب عملية، موحدة مع هوية المتجر الزرقاء والرمادية الفاتحة، وأولوية للوضوح والجداول والعمليات اليومية. تتصل لاحقًا بواجهة العميل التي تعرض حالة الطلبات ورصيد المحفظة ومعلومات المعالجة.

## وحدات الإدارة

| الوحدة | ما يديره المسؤول |
|---|---|
| نظرة عامة | الطلبات الجديدة، الطلبات قيد المعالجة، الرصيد المدفوع، الحالات التي تحتاج تدخلاً وتنبيهات المخزون/الخدمات |
| المنتجات | إضافة وتعديل وحذف المنتجات؛ الاسم والوصف والسعر والحالة والتصنيف؛ صورة اختيارية من رابط أو رفع ملف؛ الحقول المطلوبة من العميل؛ أسلوب التسليم وتعليمات ما بعد الشراء |
| التصنيفات | قائمة قابلة للإضافة والحذف وإعادة التسمية؛ أيقونة مستقلة ولون وترتيب وحالة الظهور لكل تصنيف |
| العملاء | البحث والعملاء النشطون؛ الملف الشخصي؛ سجل الطلبات؛ تعديل الرصيد بإضافة أو خصم مع سبب وسجل تدقيق؛ تعطيل/حذف حساب ضمن سياسة لاحقة |
| الطلبات | قائمة قابلة للفرز والفلترة؛ حالات جديد وقيد المعالجة وبانتظار بيانات العميل ومكتمل ومرفوض وملغى؛ محادثة داخلية؛ ملاحظات داخلية؛ إرسال كود/بيانات التسليم وتغيير الحالة |
| نماذج المنتج | حقول ديناميكية يُعرّفها المسؤول لكل منتج، مثل البريد الإلكتروني والاسم الكامل واسم المستخدم ومعرّف الجهاز؛ نوع الحقل وإلزاميته ووصفه والتحقق منه وقيمته الافتراضية |
| إعدادات المتجر | العنوان والنصوص وأيقونات التصنيفات وتنبيه الشراء وقواعد الطلب والهوية البصرية |

## فئات البدء

الفئات يجب أن تكون ديناميكية بالكامل. يُعرض في التصاميم خمسة اقتراحات مبدئية لأنها المذكورة في الطلب، مع بقاء الإضافة والحذف وإعادة التسمية متاحة: خدمات Server، الأدوات، تفعيل الأدوات، كراء الأدوات، ومتنوّع. يُؤكَّد العدد النهائي قبل التنفيذ البرمجي لأن الطلب ذكر أربع فئات ثم سرد خمس فئات.

## شاشات Stitch المطلوبة

1. لوحة الإدارة: مؤشرات الطلبات والعملاء والأرصدة، جدول طلبات بحاجة معالجة، اختصارات سريعة.
2. إدارة المنتجات: جدول المنتجات، البحث والفلاتر، زر إضافة منتج، صور/روابط/حالة وسعر وتعديل وحذف.
3. محرر المنتج والحقول الديناميكية: خطوات أساسيات المنتج، السعر والتصنيف، الوسائط، نموذج العميل، التسليم والنشر.
4. إدارة التصنيفات: بطاقات وجداول قابلة للتحرير مع اسم ورمز ولون وترتيب وحالة.
5. العملاء والمحفظة: جدول العملاء، ملف العميل، سجل الرصيد وإضافة/خصم الرصيد مع ملاحظات تدقيق.
6. مركز الطلبات: قائمة الحالات، صفحة معالجة الطلب، الحقول المرسلة، ملاحظات داخلية، إرسال كود، تغيير الحالة.
7. منطقة العميل: الطلبات النشطة ومرحلة المعالجة ورسائل الطلب والرصيد والمحفظة ومركز الدعم.

## قواعد الواجهة

- لا صور هاردوير أو أقسام Hero داخل لوحة الإدارة.
- استخدم أيقونات خطية حقيقية وحالات ملوّنة بوضوح، لا رموز نصية.
- كل عملية حساسة، مثل حذف منتج أو خصم رصيد، تستدعي تأكيدًا وسجل تدقيق.
- يوفر تحميل الصورة بالرفع أو الرابط، لكن المعالجة الخلفية والتخزين تنفذ لاحقًا داخل الموقع.
- تستخدم واجهة العميل عبارات مباشرة: قيد المعالجة، نحتاج منك معلومات، تم التسليم، مرفوض، ومكتمل.

## دعم WhatsApp ومراسلات الطلبات

تُضاف وحدة «صندوق دعم WhatsApp» إلى لوحة الإدارة. يرى المسؤول قائمة المحادثات مع اسم العميل ورقم الطلب والحالة ووقت آخر رسالة وعلامة غير مقروء. داخل صفحة الطلب، توجد لوحة محادثة مرتبطة بالطلب تُظهر الرسائل الواردة والصادرة، ومحادثة داخلية لا يراها العميل، وقوالب سريعة مثل: طلب معلومات إضافية، بدء المعالجة، اكتمال الطلب، التسليم، ورفض الطلب. يمكن للمسؤول إرسال تحديث الحالة للعميل عبر WhatsApp وربط كل رسالة بسجل الطلب.

منطقة العميل تتضمن زر «التحدث مع الدعم عبر WhatsApp» وزر «متابعة هذا الطلب عبر WhatsApp»، وحقل الموافقة على تلقي إشعارات الطلب. عند وجود بيانات ناقصة، تعرض صفحة الطلب الحالة «نحتاج منك معلومات» مع الحقول المطلوبة وزر فتح المحادثة. التنفيذ الحقيقي يحتاج لاحقًا WhatsApp Business Platform: رقم أعمال موثق، Phone Number ID، رمز وصول بخادم خلفي، Webhook لاستقبال الرسائل، وقوالب رسائل معتمدة لإرسال تحديثات خارج نافذة المحادثة.

## العملة

العملة الافتراضية في جميع الشاشات هي الدرهم المغربي، وتظهر بصيغة `د.م. 250` أو `250 د.م.` وفق مساحة العنصر واتجاه القراءة. تستخدم في أسعار المنتجات والباقات، إجماليات الطلبات، الرصيد المتاح، حركات المحفظة، الاستردادات، ولوحات المؤشرات. تُصمم الحقول المالية لإتاحة تغيير العملة لاحقًا من الإعدادات، لكن قيم العرض الافتراضية في النماذج التجريبية هي MAD.
