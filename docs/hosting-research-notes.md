# ملاحظات بحث الاستضافة والمعاينة المتزامنة

## المصادر الرسمية

تؤكد وثائق Vercel أن ربط المشروع بمستودع Git ينشئ نشرًا تلقائيًا عند كل دفع، ومعاينة مستقلة لكل فرع غير فرع الإنتاج. لذلك يصلح Vercel لمعاينة تغييرات واجهة React/Vite قبل دمجها في `main`، لكنه لا ينشر التعديلات غير المحفوظة محليًا؛ يجب أن تصل التعديلات أولًا إلى Git.

توضح وثائق Render أن خدمات الويب المجانية تفقد أي ملفات محلية، ومنها قواعد SQLite، عند إعادة النشر أو إعادة التشغيل أو السكون. كما أن خدمة الويب المجانية تدخل في السكون بعد 15 دقيقة بلا طلب وارد. قواعد Postgres المجانية على Render محدودة بسعة 1 GB وتنتهي بعد 30 يومًا؛ ولذلك لا تناسب قاعدة إنتاج دائمة بلا تكلفة.

تعرض Oracle Cloud موارد Always Free تشمل مثيلات Compute وتخزين Block Volume دائم، ما يجعلها الخيار المجاني الملائم تقنيًا لتشغيل Node.js مع SQLite محفوظة على قرص ثابت. لكنها تتطلب إعداد خادم Linux ونسخًا احتياطيًا ومسؤولية تشغيلية أكبر من خدمات النشر المُدارة.

## الاستنتاج العملي لـ ChriGsm

للتطوير السريع والمعاينة: استخدم **Vercel** للواجهة وGitHub كمصدر التزام. لكل فرع معاينة مستقلة، ويدفع الدمج إلى `main` نسخة الإنتاج. للتشغيل الحقيقي بقاعدة SQLite دائمة: استخدم مثيل Oracle Cloud Always Free مع قرص دائم، أو حوّل الخلفية إلى PostgreSQL قبل استعمال خدمة ويب مجانية لا تدعم الأقراص الدائمة.

## حالة ربط GitHub مع Vercel

بعد تسجيل دخول المستخدم إلى GitHub، ظهرت إعدادات التطبيقات المثبتة وفيها تطبيق **Vercel** مع صفحة الإعداد `https://github.com/settings/installations/153397089`. تحتاج هذه الصفحة إلى منح تطبيق Vercel الوصول إلى المستودع `arthur0xx/molflash` قبل أن يستطيع Vercel إنشاء مشروع Git مرتبط بهذا المستودع.
تم اختيار خيار **Only select repositories** في إعداد تطبيق Vercel، وظهرت قائمة تتضمن `arthur0xx/molflash` كمستودع متاح للتحديد. ما زال حفظ التغيير مطلوبًا لتفعيل وصول Vercel إلى هذا المستودع فقط.
تم تحديد `arthur0xx/molflash` وحفظ نطاق الوصول المقيد لتطبيق Vercel. بعد الحفظ، أعاد GitHub التوجيه إلى صفحة دخول Vercel؛ يلزم وجود جلسة Vercel مرتبطة بالحساب لإكمال إنشاء المشروع عبر لوحة Vercel.
