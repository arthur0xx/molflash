# قائمة جاهزية نشر chrigsm

استخدم هذه القائمة قبل نشر الموقع للعامة. المشروع يعرض كتالوجاً محلياً فقط؛ لا يرسل طلبات إلى مزود خدمات خارجي.

## 1. البيئة والأمان

| العنصر | المطلوب |
|---|---|
| `NODE_ENV` | عيّنه إلى `production`. |
| `JWT_SECRET` | استخدم قيمة عشوائية طويلة وفريدة ولا تحفظها في Git. |
| `CORS_ORIGIN` | عيّن نطاق الواجهة النهائي، مثل `https://example.com`. يمكن فصل عدة نطاقات بفواصل. |
| المدير الأول | عيّن `ADMIN_NAME` و`ADMIN_PHONE` و`ADMIN_PASSWORD` فقط عند إنشاء قاعدة بيانات جديدة، ثم أزلها من البيئة. |
| قاعدة البيانات | انسخ `backend/data/store.db` احتياطياً قبل كل نشر أو ترقية. |

انسخ `backend/.env.example` إلى `backend/.env` للتطوير المحلي فقط. في منصة الاستضافة، ضع المتغيرات في إعدادات المنصة بدلاً من إنشاء ملف أسرار داخل المستودع.

## 2. الكتالوج والصور

1. افتح لوحة الإدارة ثم **الأدوات والباقات**.
2. اضغط **تصدير الصور الناقصة** لتحصل على JSON يحوي الأدوات التي تستخدم الأصل الافتراضي.
3. ضع صورة واحدة موثوقة لكل أداة في `frontend/public/assets/tools/` بالاسم المقترح.
4. حدّث الأداة من لوحة الإدارة إلى **صورة أداة محفوظة** واكتب مساراً محلياً يبدأ بـ`/assets/tools/`.
5. احتفظ بصورة chrigsm الافتراضية للأدوات التي لا يتوفر لها أصل موثوق؛ لا تكرر صوراً للمدد أو التجديدات.

## 3. الفحص قبل النشر

```bash
cd backend
node --check src/server.js
node --check src/routes/admin.js

cd ../frontend
npm run build

cd ..
git diff --check
```

تأكد من أن قاعدة البيانات لا تحتوي حسابات اختبار أو طلبات تجريبية، ومن أن إنشاء الطلبات لا يتصل بأي مزود خارجي.

## 4. ما لا يزال منفصلاً عمداً

لا توجد حالياً عملية ربط API حي لتنفيذ الطلبات أو خصم رصيد لدى المزود. يجب تنفيذ ذلك كمشروع منفصل بعد تحديد المزود، طريقة المصادقة، معالجة الأخطاء، واستراتيجية الاختبار غير المؤذية.
