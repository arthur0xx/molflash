# قرار إعادة بناء ChriGsm وسير المعاينة الحية

**الحالة:** قرار معماري محفوظ. لا يبدأ إنشاء مشروع Firebase أو ترحيل بيانات حية حتى يقدّم المالك تأكيدًا صريحًا لبدء التنفيذ.

## البنية المعتمدة مبدئيًا

يعاد بناء ChriGsm حول **Next.js + Firebase + Vercel**. يبقى Vercel منصة النشر والمعاينات، ويصبح Next.js التطبيق الموحد للمتجر ولوحة CMC ومنطقة العميل ومسارات API الموثوقة. يوفر Firebase مصادقة المستخدمين وCloud Firestore للبيانات الموحدة وتحديثات الواجهة الفورية وStorage لأصول المنتجات والتصنيفات.

| الطبقة | التقنية | المسؤولية |
|---|---|---|
| واجهة المتجر | Next.js / React | الكتالوج والبحث وتفاصيل الخدمة والسلة والطلب |
| منطقة العميل | Next.js / React | الطلبات، الحالة الحية، الرصيد، الرسائل والدعم |
| لوحة CMC | Next.js / React | المنتجات والتصنيفات والعملاء والمحافظ والطلبات والتسليم |
| قاعدة البيانات | Firebase Authentication + Cloud Firestore | الهوية والأدوار والمنتجات والطلبات والمحافظ وسجل التدقيق |
| ملفات الصور | Firebase Storage | صور المنتجات وأيقونات التصنيفات والمرفقات |
| العمليات الحساسة | Next.js Route Handlers + Firebase Admin | تغيير الرصيد، معالجة الطلبات، أكواد التسليم، الويبهوكس |
| الاستضافة | Vercel | إنتاج ومعاينات تلقائية لكل فرع أو Pull Request |

## ما لا نستخدمه كقلب النظام

لا يُستخدم NocoDB كقاعدة التطبيق أو مصدر الحقيقة للأرصدة وأكواد التسليم. يمكن إضافته لاحقًا كواجهة تشغيل داخلية اختيارية فقط. ولا يستخدم NestJS في النسخة الأولى؛ يصبح خيارًا لاحقًا إذا ظهرت خدمات خلفية دائمة ومعقدة تحتاج فرقًا مستقلة أو عمالًا كثيفين.

## قاعدة الأمان

لا يتصل المتصفح أبدًا بمفاتيح Firebase الإدارية. كما لا يملك العميل صلاحية كتابة الرصيد أو سعر المنتج أو كود التسليم. ينفذ كل تعديل مالي أو إداري من Route Handler خادمي بعد التحقق من الهوية والدور، ويسجل في سجل تدقيق.

## طبقتا المعاينة الحية

| الحالة | الأداة | ما يراه المالك |
|---|---|---|
| أثناء البرمجة | خادم Next.js المحلي مع Hot Module Replacement | تحديث فوري داخل المتصفح بعد كل حفظ، من دون build أو push |
| قبل الإنتاج | فرع Git/Pull Request مربوط بـVercel | رابط Preview مستقل يحدّث عند كل push للفرع |
| الإنتاج | فرع `main` في GitHub | رابط الإنتاج على Vercel بعد مراجعة واعتماد التغيير |

> هدف سير العمل: لا يُدفع أي تغيير إلى `main` مباشرة. ننشئ فرعًا لكل تعديل، نعاينه فورًا محليًا، ثم يراجع المالك رابط Vercel Preview، وبعد الموافقة فقط يُدمج إلى `main` وينشر الإنتاج.

## الخطوة اللاحقة

عند قول المالك: **«ابدأ إعادة البناء على Next.js + Firebase»**، يبدأ المشروع بإنشاء تطبيق Next.js منظم، إعداد مشروع Firebase، وإعادة بناء تدفقات المنتجات والطلبات والمحافظ بالتدريج مع الحفاظ على الموقع الحالي حيًا حتى اكتمال البديل.
