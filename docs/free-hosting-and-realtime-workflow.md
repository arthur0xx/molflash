# الاستضافة المجانية والمعاينة المتزامنة لمشروع ChriGsm

## التوصية المختصرة

أفضل بنية عملية للمشروع الحالي هي فصل **المعاينة والنشر للواجهة** عن **الخادم وقاعدة البيانات**. استخدم **Vercel** للواجهة React/Vite ومعاينات كل فرع Git، واستخدم **Oracle Cloud Always Free** لخادم Express وملف SQLite الدائم. بهذه البنية تحصل على رابط معاينة مع كل دفع إلى GitHub، ورابط إنتاج مستقر، وقاعدة بيانات لا تُمحى مع إعادة النشر.

> لا توجد خدمة استضافة عامة تتلقى التعديلات غير المحفوظة مباشرة من محرر Manus. المعاينة الخارجية تتحدث عندما يحفظ Manus التعديل في Git ثم يُدفع إلى GitHub. أمّا أثناء الكتابة، فالمعاينة المحلية المؤقتة هي الأسرع لرؤية أثر التعديل فورًا.

| الحاجة | الخيار الموصى به | السبب |
|---|---|---|
| معاينة الواجهة بعد كل تغيير محفوظ | **Vercel + GitHub** | ينشئ Vercel نشر معاينة لكل دفع إلى فرع، وينشر الإنتاج عند دفع `main`. [1] |
| واجهة الإنتاج | **Vercel** أو GitHub Pages الحالي | Vercel أفضل للمعاينات وتعيين متغير `VITE_API_BASE_URL` لكل بيئة؛ GitHub Pages صالح للواجهة الثابتة الحالية فقط. |
| API وقاعدة بيانات دائمة | **Oracle Cloud Always Free VM** | يستطيع تشغيل Node.js وSQLite على قرص دائم؛ يعرض Oracle مثيلات Compute وتخزين Block Volume ضمن Always Free. [2] |
| أسرع تجربة بلا إدارة خادم | **Vercel + Supabase** | بديل جيد إذا نُقل الخادم من SQLite إلى Postgres، لكنه ليس متوافقًا مباشرة مع `better-sqlite3` ويملك حدودًا مجانية. [3] |

## سير العمل الذي ستراه في Manus

استخدم فرعين واضحين: `main` للإنتاج و`preview` للتجارب. عند تعديل الكود داخل Manus، ابدأ المعاينة المحلية أولًا لرؤية التغيير فورًا. وعندما توافق على النتيجة، احفظ التعديلات في فرع `preview` وادفعها إلى GitHub؛ سيمنحك Vercel رابطًا خاصًا بهذا الفرع. بعد التأكد، ادمج أو ادفع التغيير إلى `main` ليحدّث رابط الإنتاج تلقائيًا. يوضح Vercel أن كل فرع غير فرع الإنتاج يحصل افتراضيًا على بيئة معاينة، بينما يطلق فرع الإنتاج نشرًا إنتاجيًا. [1]

| المرحلة | ما تفعله | ما تراه |
|---|---|---|
| تطوير فوري | تشغيل Vite والخلفية داخل Manus | معاينة محلية مؤقتة تتحدث فور حفظ الملف |
| معاينة مشتركة | دفع فرع `preview` إلى GitHub | رابط Vercel فريد للفرع |
| إنتاج | دفع أو دمج التغيير إلى `main` | الرابط الرسمي للموقع يتحدث بعد بناء Vercel |
| بيانات حية | الخلفية على Oracle VM | نفس قاعدة SQLite الدائمة للطلبات والعملاء والأرصدة |

## لماذا لا أوصي بـ Render + SQLite المجانية؟

خدمة Render المجانية مناسبة كتجربة قصيرة، لكنها ليست مناسبة لقاعدة SQLite الخاصة بمتجر. ملفات خدمة الويب المجانية مؤقتة وتُفقد عند إعادة النشر أو إعادة التشغيل أو السكون؛ تذكر الوثائق SQLite صراحةً ضمن الملفات التي تُفقد. كما تدخل الخدمة المجانية في السكون بعد 15 دقيقة بلا طلب. [4] لذلك لا تستخدمها لطلبات العملاء أو الأرصدة أو صور المنتجات.

كذلك لا أنصح بقاعدة Render Postgres المجانية لبيانات متجر حقيقية؛ فهي تنتهي بعد 30 يومًا وتفتقر إلى النسخ الاحتياطي في المستوى المجاني. [4]

## خيار Supabase المجاني: متى يكون مناسبًا؟

يصلح Supabase إذا قررت ترحيل الخادم إلى Postgres واستخدام Auth وStorage المُدارين. خطته المجانية تشمل قاعدة 500 MB و1 GB تخزين ملفات، لكنها توقف المشروع بعد أسبوع من عدم النشاط ولا توفر نسخًا احتياطيًا تلقائيًا. [3] لذلك هو ممتاز للتطوير وMVP، لكنه يحتاج قرار ترحيل تقني منفصل قبل استخدامه كقاعدة إنتاج المتجر.

## إعداد الإنتاج المقترح

ضع تطبيق الخلفية على Oracle VM باستخدام Node.js وخدمة `systemd`، واحفظ ملف القاعدة في مسار ثابت مثل `/var/lib/chrigsm/store.db`. اضبط متغيرات البيئة التالية على الخادم:

```bash
NODE_ENV=production
DATABASE_PATH=/var/lib/chrigsm/store.db
JWT_SECRET=ضع_سرًا_طويلًا_عشوائيًا
ADMIN_PHONE=رقمك
ADMIN_PASSWORD=كلمة_مرور_قوية
CORS_ORIGIN=https://رابط-واجهة-vercel
```

بعد ذلك، اربط Vercel بمستودع `arthur0xx/molflash` واختر `frontend` كمجلد الجذر، ثم اضبط أمر البناء على `npm run build` ومجلد الخرج على `dist`. أضف `VITE_API_BASE_URL=https://api.نطاقك` ضمن متغيرات بيئة Vercel، كي تتصل الواجهة بخادم Oracle بدل بيانات GitHub Pages الثابتة.

> لا تضع `JWT_SECRET` أو كلمات مرور الإدارة أو رموز API داخل Git أو في متغيرات `VITE_`، لأنها تصبح مرئية في متصفح العميل. خزّنها في إعدادات أسرار الخادم فقط.

## الخطوة التالية المقترحة

ابدأ أولًا بربط المستودع مع **Vercel** للحصول على معاينات الفروع فور كل دفع. بعد ذلك ننشئ Oracle VM ونجهّز الخلفية وقاعدة SQLite الدائمة واسم نطاق API. هذا الترتيب يمنحك نتيجة مرئية سريعة، ثم ينقل بيانات المتجر إلى بيئة مستقرة بدل قاعدة الاختبار المؤقتة.
